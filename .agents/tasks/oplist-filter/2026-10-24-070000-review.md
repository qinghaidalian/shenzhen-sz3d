## High-level view

过滤逻辑集中在 `RebuildFilteredGroups()`：先按选中种类筛组（哨兵 `Category == null` 跳过筛选），再对组内条目按关键字做 `OrdinalIgnoreCase` 子串匹配（命中 Name 或 Description，空关键字全通过），只保留非空组。两条件串联即交集，关键字清空或选「全部算子」各自回退到全集。

集合更新用 `Clear()` + 逐项 `Add`，没有 new 新集合替换 `FilteredGroups` 引用；重建的 `OperatorGroup` 复用原 `OperatorDescriptor` 实例，所以拖拽模板与 code-behind 的 `DataContext` 假设不受影响。

哨兵用带显示文本的 `CategoryOption(string Display, string? Category)` 而非裸字符串，避免「全部算子」文案与真实 Category 撞名。

MVVM 与主题约束均守住：VM 只触及 `System.Windows.Application`/`System.Windows.Input`，无 `System.Windows.Controls`；ComboBox 内联引用 Dark.xaml 已有画刷适配深色，未新增全局样式或 NuGet 依赖。

## 过滤管线与交集语义

`RebuildFilteredGroups()` 从静态只读的 `NodeLibrary.Groups` 起算，先 `Where(g => category is null || g.Title == category)` 按种类筛组，再对每组 `Items` 用关键字条件筛条目，`.Where(g => g.Items.Count > 0)` 丢弃空组。关键字条件：

```csharp
keyword.Length == 0 ||
o.Name.Contains(keyword, StringComparison.OrdinalIgnoreCase) ||
o.Description.Contains(keyword, StringComparison.OrdinalIgnoreCase)
```

空关键字短路为全通过，回退到仅受种类约束的结果；种类为 `null`（全部算子）时跳过组筛选。两条件在同一管线串联，结果即交集——需求 1、2 的「同时生效」得到满足。匹配字段限定 Name + Description，与需求一致，未误扩到 Category 或 TypeId（confirmed）。

`SearchKeyword` 与 `SelectedCategory` 的 setter 都走 `Set(ref ...)` 并在返回 true 时触发重算，`UpdateSourceTrigger=PropertyChanged` 保证逐字实时过滤（confirmed）。

## 哨兵与下拉数据源

`CategoryOption` 记录带 XML 文档注释，`Category == null` 表「全部算子」。构造函数先 `Add(new CategoryOption("全部算子", null))`，再按 `NodeLibrary.Groups` 顺序逐个 `Add(new CategoryOption(group.Title, group.Title))`，种类来源与现有分组标题一致。初始化时直接给字段 `_selectedCategory = CategoryOptions[0]` 再显式 `RebuildFilteredGroups()`，避开 setter 在构造期触发通知，首帧即显示全集（confirmed）。XAML 侧 `SelectedItem="{Binding SelectedCategory}"` + `DisplayMemberPath="Display"` 与哨兵记录配合正确。
