# 节点分组块 (Phase 1 最小可用)

把图漾 RVS 式的分组块接到 Nodify 画布：核心库新增无 WPF 依赖的 `GroupModel`、纯几何成员判定 `GroupMembership`、`GraphModel.Groups`/`AddGroup`/`RemoveGroup`、`GroupDto`+`GraphDto.Groups` 持久化 DTO 与 10 个 xUnit 单测；WPF 层引入 `CanvasItemViewModel` 抽象基类让节点与分组共存于异构 `ItemsSource`，新增 `GroupViewModel`，用 Nodify 7.3.0 内置 `GroupingNode` 渲染（ZIndex=-1 自动置后、CanResize、拖 Header 平移成员均为库内置），并复用节点右键单击删除模式接入分组删除。实现严格对齐 plan.md 的 10 步与两个 FEAT 的验收标准，构建绿、核心单测 16/16 全绿不回归。

Watch for: 所有运行时交互项（置后渲染、拖 Header 平移成员、Shift 切换、resize 手感、右键删除手感）均为 needs-verification-at-implementation，静态验证无法覆盖，须人工在 VS/Rider 启动确认 (confirmed — 计划已显式标注，非打回项)。`RecomputeMembership` 的 `_membership` 映射目前只在增删分组后刷新、且无任何读取方，是 Phase 1 占位实现 (confirmed)。

**Verdict**: APPROVED

## High-level view

核心库与 WPF 的隔离做得干净。`GroupModel`/`GroupMembership`/`GroupDto` 全部落在 `Sz3D.Core.Infrastructure`，不引任何 WPF 类型，几何判定（闭区间含边界、重叠取最小面积）有单测兜底。`GraphModel.RemoveGroup` 只删分组本身不碰 `Nodes`/`Connections`，并有 `RemoveGroup_KeepsMemberNodes` 单测锁定这条语义——这正是"删除分组不删成员节点"需求的证据。

异构 `ItemsSource` 的架构选择是本次改动的重心。引入 `CanvasItemViewModel` 基类统一 `Location`/`IsSelected`/`DeleteCommand`，让一个 `ItemContainerStyle` 同时服务节点与分组，再靠两个按 `DataType` 分流的 `DataTemplate` 把 `NodeViewModel`→`nodify:Node`、`GroupViewModel`→`nodify:GroupingNode`。`NodeViewModel` 的对外绑定（Title/Location/IsSelected/DeleteCommand/Input/Output/Parameters）在重构后保持不变。

分组的置后渲染与拖拽平移成员完全依赖 Nodify 7.3.0 的 `GroupingNode` 内置行为，XAML 未显式写 ZIndex。这把唯一需要自写的几何逻辑收敛到 `GroupMembership`，是合理的减负，但代价是这些交互在本工程下的实际表现无法由构建/单测证明，必须人工跑起来看。

右键删除分组复用了既有的 `OnNodeRightButtonDown` 同构模式新增 `OnGroupRightButtonDown`，`OnNodeRightButtonDown` 与 `Dark.xaml` 的 MenuItem 模板均未被触碰，符合"不要动"约束。

### 核心库与 WPF 隔离，几何逻辑有单测兜底

`GroupModel` 以左上角坐标 + 宽高描述矩形，仅暴露 `Id`(init)/`Title`/`X`/`Y`/`Width`/`Height`/`Color`，无 WPF 引用，镜像 `NodeModel` 风格。`GroupMembership` 的三个方法都对 null 参数 `ArgumentNullException.ThrowIfNull`，`Contains` 用闭区间含边界，`GroupContaining` 用 `OrderBy(面积).FirstOrDefault()` 取最小面积的包含分组（嵌套时返回最内层）。

`GraphModel.RemoveGroup` 的语义是本次需求的关键：

```csharp
public Result RemoveGroup(Guid groupId)
{
    var group = Groups.FirstOrDefault(g => g.Id == groupId);
    if (group is null) return Result.Fail($"Group {groupId} not found.");
    Groups.Remove(group);   // 不触碰 Nodes / Connections
    return Result.Ok();
}
```

`RemoveGroup_KeepsMemberNodes` 单测把一个节点放进分组区域、删分组后断言 `Nodes` 仍含该节点，直接验证了"删除分组不删成员"。边界点命中、多重叠取最小面积、未知 Id 返回失败均有对应 `[Fact]`，10 个新增测试 + 6 个基线共 16 个全绿。

### 异构 ItemsSource 与基类统一绑定

`CanvasItemViewModel` 把 `Location`（virtual，`Set` 成功后调 `OnLocationChanged` 钩子）、`IsSelected`、`DeleteCommand` 上提为公共契约。`NodeViewModel` 与 `GroupViewModel` 各自 `override OnLocationChanged` 回写模型 `X`/`Y`。`NodifyEditor.ItemsSource` 改绑 `Items`（`ObservableCollection<CanvasItemViewModel>`），`Nodes` 保留为执行/连线的权威集合并带注释说明，`AddOperator` 末尾同时 `Items.Add(vm)`、`DeleteNode` 同步 `Items.Remove(vm)`。基类用 `System.Windows.Point`/`System.Windows.Input.ICommand`，grep 确认 ViewModels 目录无 `System.Windows.Controls` 引用。

`GroupViewModel.Size` 的 getter 构造 `new Size(Model.Width, Model.Height)`、setter 回写模型宽高，供 `GroupingNode.ActualSize` 的 `Mode=TwoWay` 绑定——resize 完成后尺寸能回到模型。

### 依赖 Nodify 内置行为的置后与平移

XAML 的 `GroupViewModel` 模板只声明 `Header`/`ActualSize`/`CanResize`/`HeaderBrush`/`PreviewMouseRightButtonDown`，没有显式 ZIndex；置后（ZIndex=-1）、拖 Header 的 `SelectArea`+Group 平移、Shift 切 Self 全由 `GroupingNode` 控件自身提供。这把自写代码收敛到几何判定一处，但这些交互在本工程 Nodify 7.3.0 下的真实渲染/手感无法由构建或单测证明，是人工验收的重点。

### 右键删除复用且未动受保护区

`OnGroupRightButtonDown` 与 `OnNodeRightButtonDown` 同构（`sender is FrameworkElement { DataContext: GroupViewModel group }` → `group.DeleteCommand.Execute(null)` → `e.Handled = true`）。`OnNodeRightButtonDown` 文本、`nodify:Node` 的 `PreviewMouseRightButtonDown` 挂接、`Dark.xaml` 的 MenuItem 模板均未改动，符合 plan.md 的"不要动"约束。`DeleteCommand` 在 `CreateGroup` 与 `AddOperator` 中都显式注入，右键删除路径不会命中 `null!` 默认值。

### 成员映射占位

`RecomputeMembership` 遍历 `Nodes` 用 `GroupContaining` 填 `_membership` 字典，当前仅在 `CreateGroup`/`DeleteGroup` 后调用，且没有读取方。拖动节点进出分组不会触发重算。plan.md 已把持久化成员关系的拖拽回调划在 Phase 1 范围外，这里只是占位，不影响本阶段验收，后续接入 .rvsp 往返时需补齐刷新时机与读取。
